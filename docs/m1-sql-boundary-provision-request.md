# SQL boundary M1 — danh sách provisioning chờ người dùng duyệt

Chưa tạo login/user/role/grant, chưa áp DDL. Khảo sát chỉ đọc ngày 24/10/2026: LocalDB `KLCN_M1_Test`/`MSSQLLocalDB` hiện hữu, LocalDB 17.0.4025.3 thuộc tài khoản hiện tại; service `MSSQL$SQLEXPRESS` hiện hữu nhưng Stopped. Chưa khởi động service, chưa xác nhận SQL authentication/TLS/admin access của SQLEXPRESS. Không cài SQL/VM/OS user/ACL hoặc đổi SQL dùng chung.

## Phạm vi đề nghị cho một run, không phải quyền hiện có

- Instance candidate: `.\SQLEXPRESS` **chỉ nếu DBA/người dùng cho phép start và xác nhận hỗ trợ SQL login/TLS**. Không tự bật Mixed Mode/restart/thay cấu hình instance. Nếu không phù hợp, DBA chỉ định instance test hiện hữu khác; không fallback dùng sa hoặc LocalDB-owner làm app/operator.
- RunId đề nghị `m1br_20261024_01`; hai DB `KLCN_M1_Test_Boundary_m1br_20261024_01` (clean), `KLCN_M1_Test_Legacy_m1br_20261024_01`. Tất cả dữ liệu synthetic; không tái dùng DB dùng chung. Bắt đầu bằng xác nhận tên chưa tồn tại; trùng thì dừng, không xóa/ghi đè.
- Hai SQL login mới: `m1br_20261024_01_app`, `m1br_20261024_01_operator`; password ngẫu nhiên do DBA/secret manager cấp, không argv/Git/log. Mỗi login chỉ mapped user cùng tên trong hai DB test, role `m1_app` hoặc `m1_operator` tương ứng; không kiêm role, không server roles/DDL/ownership/impersonation hoặc grant option.
- Principal deployment do DBA giữ riêng, tạo DB/migrate/apply script/fixture. Không cấp deployment credential cho API/operator. Không đổi users/grants/public/nested roles đã tồn tại trong DB khác.
- Chỉ role/grants trong `database/m1-sql-boundary-up.sql`: guard Employee/audit dùng CALLER, permission dictionary do deployment seed. DDL migration bảo mật này là bước apply riêng có quyền DBA, không EF/API/CLI auto-run. Không giả DDL đã được chạy khi chỉ build.

## Lệnh apply/assert cần thực hiện sau khi được phép

1. DBA kiểm `SERVERPROPERTY('IsIntegratedSecurityOnly')`, TLS, login hiệu lực/DB grants và khả năng tạo đúng hai DB. Cấu hình instance không phù hợp thì dừng và báo, không tự sửa chung. Không ghi connection string/password ra output.
2. Tạo hai DB bằng deployment principal. Clean DB: `dotnet ef database update --project backend/src/TiemChung.Infrastructure --startup-project backend/src/TiemChung.Api` với secret connection deployment trỏ đúng clean DB. Legacy DB: migrate đến InitialCreate, seed Admin/nhân viên giả bằng deployment, sau đó migrate M1 như contract. Không đổi migration cũ.
3. Apply `database/m1-sql-boundary-up.sql` bằng deployment connection **trong đúng từng DB test**. DBA tạo login bằng secret manager/parameterized admin driver, `CREATE USER [login] FOR LOGIN [login]`; `ALTER ROLE m1_app ADD MEMBER [app]` và `ALTER ROLE m1_operator ADD MEMBER [operator]`. Không truyền password qua `sqlcmd -v/-P` hoặc shell history. Script không tự tạo logins hoặc lấy quyền caller từ config.
4. Fixture deployment: tạo `FixtureOnly(Id CHECK Id=1)` và row 1 trong hai DB synthetic; `GRANT SELECT ON dbo.FixtureOnly TO m1_app` **chỉ trong hai DB test** để synthetic readiness chạy. Seed một NhanVien Admin và ít nhất một LeTan chưa có account; sau CLI bootstrap còn một Employee có account và một NhanVien chưa liên kết để test INSERT guards. Fixture không ở runtime app/operator. Dữ liệu/code quyền đã được deployment seed; operator không được INSERT QuyenHan.
5. Kiểm DB role/effective permissions, sys.database_permissions/public/column grants; trigger module `execute_as_principal_id IS NULL`, enabled, guard marker 1. App không SELECT audit/ledger, không DML employee/grants/metadata, không ALTER trigger/role. Operator không DDL/meta/audit update/delete; SQL context không dbo/sa/owner. Role/membership query không đủ thay thử DML denial.
6. Set secret connection của **hai runtime logins** vào `M1_BOUNDARY_APP_CONNECTION`, `M1_BOUNDARY_OPERATOR_CONNECTION`; chạy `dotnet test backend/tests/TiemChung.BoundaryAcceptance/TiemChung.BoundaryAcceptance.csproj -c Release`. Suite riêng fail nếu thiếu connections, không skip/PASS và không tự provision; kiểm app DML denial (old/new/MERGE/multirow/audit), operator permissions và HTTP app register→host worker→verify→login/refresh/logout/Profiles; CLI process app bị chặn trước prompt. Không dùng `EXECUTE AS` hoặc DBA connection để thay login thật.
7. CLI positive: publish riêng `dotnet publish backend/tools/TiemChung.IdentityOperator -c Release`; launcher giữ operator connection qua secret env `M1_OPERATOR_CONNECTION`. `dotnet <operator.dll> bootstrap-admin` trên clean DB, nhập employee ID/username/password qua terminal ẩn. Assert DB/audit bằng deployment read-only, bootstrap lần hai bị chặn.
8. Legacy DB maintenance: deployment đọc DB ID/epoch/migration/target/version mới sau migrate và chuẩn bị manifest ngoài Git; `M1_RECOVERY_MANIFEST` chỉ đường dữ liệu request, không tạo quyền. CLI `recover-upgraded-admin`; kiểm ledger/retry/quota/audit server SQL identity, target hash/status/duty/quyền đúng. Sai DB/version, hai process cạnh tranh, audit failure rollback phải được ghi evidence. Không dùng manifest mới để reset quota.
9. `reset-employee-password` bằng cùng SQL operator login + actor app Admin mới sau recovery; nhập credential ẩn, target IDs/RowVersion; kiểm negative actor/quyền/self/Director/stale, hai CLI process cùng version một commit. Tạo phiên bằng API app login trước reset, kiểm token cũ vô hiệu và password mới login sau reset. Audit hash/revoke lỗi rollback và ledger giữ nguyên. Không truyền secret bằng pipe/stdin redirect để giả terminal; các ca terminal này **chưa tự động hóa/kiểm chứng** ở lượt hiện tại.

## Tác động và cleanup sau run

Chỉ tạo hai DB, hai logins/users và object/grants trong đúng hai DB mới. User cần chấp thuận provisioning cụ thể trên instance DBA xác nhận trước thao tác. Không sửa ACL/OS account hay quyền runtime hiện có. Giữ evidence không PII/secret (SHA, exit code, count, SQL identity, audit/ledger IDs, auth status).

DBA xác nhận runId/ownership rồi drop đúng hai DB test và đúng hai login mới sau thu hồi secret, không wildcard/drop object dùng chung. Không down migration bảo mật trên DB có dữ liệu thật để lộ lại Employee; production rollback là fail-closed/backup do DBA, không tự xóa ledger. Start service chỉ nếu được cho phép, khôi phục trạng thái theo phê duyệt ban đầu. Nếu không được cấp instance/logins/grants thì dừng **phần acceptance principal/CLI**, code/regression/build vẫn tiếp tục; không gọi M1 đủ nghiệm thu.
